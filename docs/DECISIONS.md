## Как работаем (правила для всех сессий и агентов)
- Контракты в `docs/` меняет только координатор (главная сессия). Поток, которому нужна
  правка, пишет её в отчёт `contract_issues`.
- Каждый поток пишет только в свои файлы (таблица в PLAN.md). Ветки `wave-N/<поток>`,
  worktree на поток, слияние — координатор.
- Сборка — Opus, ревью — Fable (строго, отдельный раздел безопасности), механика и тесты — Sonnet.
- Честность и транспорт — PROTOCOL.md §1 и §6: только `/partner <JSON>` по RCON,
  никогда `/c`/`/sc`; без телепорта и предметов из воздуха.
- Готово для потока = юнит-тесты + ревью без блокеров + живой сценарий на тестовом сервере.
- Репозиторий публичный: никаких личных путей, адресов, паролей, журналов игры и отчётов
  агентов с путями — это в `CLAUDE.local.md`, `tools/pc/pc.local.json` и вне репозитория.

## Решения автора
- 2026-09-27: второй персонаж в сейве игрока (`character` без клиента, управляет мод);
  только легальные действия; живое время без паузы, Claude просыпается по событиям,
  рефлексы в моде; отдельный репозиторий и мод; связь RCON + MCP на Python; состояние текстом.
- 2026-10-06: **достижения важны** — на рабочем сейве никаких `/c`/`/sc`, в т.ч. по RCON.
  Потом — режим нескольких помощников: id помощника в каждой команде и событии с первого дня.
- 2026-10-08: пишем **своё** (не форк linsyking); тесты на сервере без окна по SSH;
  **v1 = поручение целиком** («поставь добычу на этой руде»). Планирование в v1 —
  **призраки от игрока** (моды Mining Patch Planner, P.U.M.P., чертежи) **или forge**;
  модуль производства (по образцу Rate Calculator) — в v1; встроить алгоритм MPP — кандидат v2.
  Разработка — через Workflow, параллельными потоками.
- 2026-10-09: репозиторий открыт (MIT), разработка дальше — в публичном репозитории.
- 2026-10-13: **разметка добычи по алгоритму MPP — в v1** (режимы simple/compact/super_compact/…,
  трубы; код раскладок берём из мода, MIT); свой поиск по базе `find` (образец — Factory Search);
  число помощников задаёт игрок при запуске; чертежи ставятся как с Shift (отсыпка, фундамент,
  снос деревьев), Ctrl+Shift — только с согласия игрока. **Два вида тела по флагу запуска:**
  тело без игрока (как сейчас, по умолчанию) или персонаж второго подключённого клиента игры —
  управляет им тот же мод, а не мышка; рамки чужих модов через второй клиент — после v1.
- 2026-10-13: **лента от добычи до базы — в v1** (`plan_belt`, поиск пути в обход жидкости и построек,
  подземные только где игра разрешает). Планировщик лент MPP не годится (прямые и углы, без обхода).
  Основа — код Wuastbude Belt & Pipe Router (MIT), если подойдёт, иначе свой.
- 2026-10-13 (после волны 3): **работать без фундамента обязательно** — он открывается в конце игры.
  Свойства плиток (чем накрыть, можно ли пройти, идут ли подземные) брать **из игры**, без имён в
  коде — планеты из модов должны работать. Если хоть одна клетка чертежа на плитке без возможной
  подложки — не ставить, а искать сдвиг или другое место (обрезать только с согласия игрока);
  помощник должен понимать форму суши: у участка в лавовом озере может быть один узкий выход
  (операция `access`).
- 2026-10-13 (после волны 4): новое тело помощника — через **10 секунд**, как возрождение в игре;
  в первые 5 минут после ухода прежнего тела оно появляется в точке возрождения и идёт пешком.
  Обычный режим постройки (без Shift) на плитке без опоры ведёт себя как Shift: не ставит и ищет
  сдвиг. Узкий выход с участка — предупреждение, а не отказ.
- 2026-10-14: **основной режим — тело без игрока; второе окно не нужно.** Хозяину хватает имени над
  головой и метки на карте: мод рисует подпись и держит метку на карте силы, тем же именем подписан
  чат (настройка `partner-helper-name`, по умолчанию «Claude»). Строки в списке игроков нет — это
  можно только вторым клиентом, он остаётся запасным режимом.
- 2026-10-13: **планируем по карте, на месте перепроверяем.** В открытых местах без обзора прокладка
  лент учитывает всё, что стоит на карте: плитки, скалы, свои постройки и гнёзда кусак («гнездо на
  карте есть — обходим, старое оно или новое, неважно»). Подвижных врагов не учитывает. Подойдя,
  помощник перепроверяет: если призрак невыполним или рядом враг — останавливается, убирает свои
  призраки впереди и перекладывает этот кусок заново. Делается после хвостов 3.4.

## Факты, проверенные в игре (2026-10-06/09)
Подробно: `research/ingame-run-2026-10-06/RESULTS.md`, `research/live-e-2026-10-08.md`.
- У персонажа без игрока работают: ходьба (`walking_state` держится сам), `request_path`,
  добыча (не выключается сама), `begin_crafting`, личные дроны, машина, смерть + труп с вещами.
- **Событий крафта нет** (`on_player_crafted_item`) — опрашивать очередь.
- **Карту сам не открывает**, даже при игроке онлайн → обзор через `force.chart`; без игроков
  онлайн он работает для силы игрока, но не для силы из `create_force`.
- Призрак на непостроимом месте → дроны вечно висят над ним: ставить только после `can_place_entity`.
- `helpers.send_udp` вешает игру на 11 с — не использовать.
- RCON при хосте из меню работает (8–24 мс), команда до 1 МБ проходит;
  **команды мода по RCON достижения не отключают**.
- `game.get_entity_by_unit_number` в 2.0 находит не все сущности — цель с `pos` (ACTIONS.md).
- Моды MPP, P.U.M.P., Rate Calculator программного входа не имеют (только инструмент
  выделения в руках игрока); у helmod есть `helmod_interface`. MPP и Rate Calculator — MIT,
  у P.U.M.P. лицензии нет — его код не берём.

## Связи
- factorio-forge — проектирование чертежей, профили сейвов, мод-спутник. Напарник пользуется
  forge (`partner_plan`), а не дублирует его. Команды плиточной карты в forge нет.
- Опыт прошлого проекта автора (Claude играет в Among Us через мод): тонкий MCP над `core` с
  валидацией, ожидание событий по номеру с фильтром шума (≤ 55 с), два соединения, мало
  инструментов, рефлексы списком целиком, агент на каждого игрока с ключом места.
- Отвечать по-русски, просто.
