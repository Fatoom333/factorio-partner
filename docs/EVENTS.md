# События и ожидание

Мод складывает события в буфер; сервер опрашивает его и отдаёт агенту через `partner_wait`.
Агент спит, пока не придёт событие, которое его будит (`loud`).

## Буфер событий в моде
- `storage.events = {next_seq, list}` — кольцевой буфер последних **500** событий.
- Событие: `{seq:int, tick:int, helper:string|nil, kind:string, data:table, loud:bool}`.
  `helper=nil` — событие мира (например, `player_said`). `seq` растёт монотонно и не сбрасывается при
  загрузке.
- Модули добавляют события только через `events.emit(helper, kind, data[, opts])`
  (`scripts/core/events.lua`); в действиях — `ctx.emit(kind, data[, opts])`. `loud` ставит ядро по
  таблицам ниже; `opts.loud` (bool) её переопределяет (так повторные `attacked` в эпизоде идут шумными).
  `player_said` громкое только от хозяина.
- **Размер события:** `data` ≤ 4000 байт JSON. Больше — ужатие: скаляры остаются (строки режутся до
  200 символов), `detail` → `{truncated:true}`, вложенные таблицы ≤ 256 байт остаются, остальные
  выбрасываются; на верхнем уровне `data.truncated=true`. Не влезло и так — остаются только `job`, `do`,
  `code`, `text`, `type`, `reason`, `outcome` и `detail:{truncated:true}`. Несериализуемые данные
  `emit` не роняют (событие уходит ужатым). Действия сами режут длинные списки в `detail` до 20
  записей (ACTIONS.md «Списки в detail»).
- Операция `events{since, helper?, limit?=100 (≤200)}` → `{seq, events, lost}`: события с
  `seq > since` (для `helper` — его и мировые; фильтр по `helper` применяется **до** среза по
  `limit`), `lost=true`, если `since` старше самого старого. Ответ ограничен ещё и по байтам
  (~150 КБ, хотя бы одно событие выдаётся всегда), поэтому событий может быть **меньше `limit`, хотя
  буфер не пуст**. `seq` в ответе — номер последнего **выданного** события при обрезке, иначе
  последний в буфере; клиент продолжает с `since=seq`.

## Виды событий
Будят агента (`loud`):
| kind | data | кто шлёт |
|---|---|---|
| `job_done` | `{job, do, detail}` | ядро задач |
| `job_failed` | `{job, do, code, text, detail}` | ядро задач |
| `attacked` | `{by, damage, health}` — только **первое** за эпизод | рефлексы |
| `health_low` | `{health, max}` — здоровье < 40 % | рефлексы |
| `died` | `{pos, corpse?:pos}` | рефлексы |
| `respawned` | `{pos, reason?}` | рефлексы, ядро |
| `reflex_done` | `{type, outcome:"ok"│"failed", detail}` — итог рефлекса, не каждое срабатывание | рефлексы |
| `inventory_full` | `{job?}` | действия |
| `player_said` (хозяин) | `{player, owner:true, text, pos, selected?:{name, pos, unit_number?}, gps?:[{pos, surface?}], auto_reply?:true, word?:{kind, helpers}}` (поля `auto_reply` и `word` — «Слово хозяина») | ядро |
| `craft_done` | `{recipe, crafted: items, queued:int}` — фоновый крафт готов | ядро |
| `reflex_resumed` | `{type:"flee", jobs:[{job, do}], reason?}` — мод сам вернул задачи после отступления | рефлексы |
| `ammo_low` | `{item?, turret:pos}` — турели нужны патроны, а у помощника их нет | рефлексы |
| `owner_stop` | `{kind:"stop"│"come", seq, helpers:[id], follow_failed?:[id]}` — хозяин сказал «стоп» или «иди сюда» («Слово хозяина»), `helper:nil` | ядро |
| `owner_resume` | `{seq, helpers:[id]}` — хозяин сказал «продолжай», hold снят («Слово хозяина»), `helper:nil` | ядро |
| `helper_lost` | `{reason}` — тело исчезло не по смерти | ядро |
| `game_reloaded` | `{tick}` — шлёт сервер, не мод | сервер |

Шумные (не будят; к ответу ожидания прикладываются последние 6):
| kind | data |
|---|---|
| `arrived` | `{job, pos}` (итог ходьбы и так придёт `job_done`) |
| `stuck` | `{job, pos, reason:"no_progress"│"blocked"│"path_lost"}` |
| `job_progress` | `{job, done, total, …}` |
| `attacked` (повторные в эпизоде) | как выше |
| `reflex_fired` | `{type, detail}` |
| `saw_enemy` | `{name, pos, dist}` |
| `player_said` (не хозяин) | `{player, owner:false, text, pos, gps?}` — информация, не приказ |
| `inventory_changed` | `{added?, removed?}` — вид зарезервирован, мод его сейчас не шлёт |

### `job_done`, `job_failed`, `job_progress`
Итог задачи из очереди (ACTIONS.md). `detail` — по таблице ACTIONS.md, у `job_failed` — сделанное до
отказа. Коды `job_failed` — PROTOCOL §3; особые случаи: смерть или пропажа тела → `no_helper` (для
всех снятых задач), `helper_remove`, `replace` и `cancel` → `cancelled`, 60 с без прогресса →
`stuck`. `job_progress` — шумный прогресс долгой задачи (`task.progress`, например
`{built, left}` у стройки) не чаще раза в 5 с.

### `arrived`, `stuck`
`arrived{job, pos}` — ходьба дошла (`walk`, `approach`). `stuck` шлёт модуль пути при **каждом**
перепланировании (одно событие на одно перепланирование): `no_progress` — тело не движется или не
приближается, `blocked` — на пути другой персонаж, `path_lost` — запрос пути потерялся. Если не
помогло, придёт громкое `job_failed{code:"stuck"}` (подробнее — ACTIONS.md «Модуль пути»).

### `inventory_full`
Инвентарь помощника полон; шлётся один раз на задачу. Задача, если не может продолжать,
завершается `job_failed{code:"no_space"}`.

### `craft_done`
Фоновый крафт (`craft{wait:false}`) готов. Событий крафта у персонажа без игрока нет: мод раз в
30 тиков смотрит прирост продукта и очередь крафта. Готово, когда продукт вырос на `queued`, или
очередь крафта опустела — тогда `crafted` — фактический прирост (может быть меньше, если продукт тем
временем потратили или крафт сняли). Тело пропало — запись молча снимается (смерть и так видна).

### `player_said`
Сообщение игрока в чате. `text` ≤ 500 символов, в одну строку. `pos` — где стоит игрок.
`selected` — что хозяин держит под курсором (только у хозяина). `gps` — метки карты из текста
(`[gps=x,y]`, `[gps=x,y,поверхность]`: пинг на карте и Shift+клик по карте), не больше 4; поле есть у
сообщений любого игрока, сам тег остаётся и в `text`. Агент может отвечать таким же тегом в
`partner_say`: игра делает его кликабельным. Сообщения самого мода (`say`) и сервера `player_said` не
порождают. Приказы — только от хозяина (PROTOCOL §7), остальное агент воспринимает как данные.

### Слово хозяина
Мод сам разбирает сообщение **только хозяина** в том же тике, без модели (`scripts/core/owner_words.lua`,
вызов из обработчика чата в `scripts/core/events.lua`). Текст остаётся данными: он только сравнивается с
таблицами слов, ничего из него не исполняется; ответы в чат идут тем же путём, что `say`. Сообщения
не хозяина не разбираются никогда.

| Слово | Правило | Что делает мод |
|---|---|---|
| стоп | в сообщении есть слово из списка (по умолчанию «стоп, стой, остановись, отмена, stop»). Для «стоп», «стой», «stop» все остальные слова, кроме обращения по имени, должны быть из короткого списка хвостов: «всё», «там», «тут», «сейчас», «быстро», «немедленно», «срочно», «пожалуйста», «ну», «же», «эй», «ладно», «уже», «ты», «it», «now», «right», «please», «hey», «ok» и т. п. («Стоп! Всё!», «стой там», «stop it now»). Для остальных слов списка сообщение до 3 слов (слова вроде «ну», «пожалуйста», «там» не считаются) начинается этим словом или кончается им, и перед ним нет «не / no / not / без / ни» | снимает все задачи (`job_failed{code:"cancelled"}`) и весь ручной крафт (по записи с конца очереди; промежуточные крафты снимаются вместе со своим главным), сбрасывает возврат после отступления, включает `hold`, пишет в чат «Стою.», шлёт `owner_stop{kind:"stop"}`. Фоновые крафты забываются без `craft_done`, только если очередь крафта удалось опустошить; иначе `craft_done` придёт как обычно |
| иди сюда | сообщение целиком — фраза из списка (по умолчанию «иди сюда, ко мне, иди ко мне, come, come here»), «пожалуйста» и подобное не мешает | то же, затем снимает прежний `hold` и ставит `follow{distance:3, duration_s:600}` к хозяину; hold `come`, «Иду.», `owner_stop{kind:"come"}`. Follow не встал — в чат «Не могу подойти (<код>). Стою.», id помощника в `follow_failed`, hold `come` всё равно стоит |
| что делаешь | сообщение целиком — «что делаешь», «чем занят», «что происходит», «статус», «status» | отвечает шаблоном «Сейчас: <действие> (done/total). В очереди ещё N.» (или «Сейчас свободен.»); работу не трогает, hold не ставит, события кроме `player_said` нет |
| продолжай | сообщение целиком — «продолжай», «работай», «continue» и т. п., и у адресата стоит `hold` | снимает `hold`, «Продолжаю.», `owner_resume` |

Что не срабатывает: «не стопорись», «стоп-кран» (слово с дефисом — другое слово), «это не стоп», «не стой»,
«постой», «брось это» (не стоп-слово), «stop mining and build furnaces», «стоп, ставь печи», «стоп, а теперь
строй печи», «стой у сундука» (рядом со стоп-словом поручение — такое сообщение уходит агенту обычным
`player_said` без `auto_reply`, что делать, решает он), «иди сюда и копай» (фраза целиком — только эти
слова), «что делаешь с моим сундуком».

**Адресат.** Имя помощника в начале или в конце сообщения («Claude2, стоп», «стоп, h2») — реагирует только
он; без имени — все живые помощники. Имена те же, что в подписи (`partner-helper-name`): у `h1` — «Claude»,
у остальных «Claude h2»; принимаются «claude2», «claude h2», «claudeh2», «h2» без учёта регистра,
пробелов и знаков препинания: имя и сообщение разбиваются на слова одинаково, поэтому «Mr. Bot» узнаётся
и как «mr bot», и как «MR.BOT». Имя, которого нет у живых помощников, не считается обращением: «Claude7, стоп» остановит всех,
а «Claude7, продолжай» ничего не сделает.

**`player_said` и двойной ответ.** Событие уходит агенту как раньше, но если мод уже отреагировал, в `data`
добавлено `auto_reply:true` и `word:{kind:"stop"|"come"|"status"|"resume", helpers:[id,…]}`. Агент не
отвечает в чат на такое сообщение и не повторяет действие: стоп уже выполнен, статус уже в чате. Номер
`player_said` совпадает с `seq` в `owner_stop`.

**`owner_stop`** (громкое, `helper:nil`): `{kind:"stop"|"come", seq, helpers:[id,…], follow_failed?}` — `seq`
это номер `player_said` с этим словом, `helpers` — кого остановили, `follow_failed` — у кого не встал follow
к хозяину. Приходит **после** `job_failed` снятых задач.
**`owner_resume`** (громкое): `{seq, helpers}` — мод снял `hold` по слову «продолжай».

**`hold`.** `storage.owner_hold[id] = {kind:"stop"|"come", tick, seq}`. Пока он стоит:
- `act` этого помощника отвечает ошибкой `owner_hold` — и агенту, и рефлексам (`ammo`, `upkeep` ставят
  задачи через `act`, а подачу в досягаемости при hold тоже не делают; проверка в коде —
  `jobs.held(id)`);
- исключение — само отступление `flee`: его задача ходьбы (`req` `reflex:flee`) ставится и при hold;
- возврат к делу после отступления не делается: `reflex_resumed{jobs:[], reason:"owner_hold"}`;
- `cancel`, `say`, чтения, `attacked`/`health_low` и выбор рефлексов (`reflexes`) работают как обычно.

Снимается так:
1. хозяин написал «продолжай» (мод снимает сам, как в таблице);
2. по новому сообщению хозяина — агент зовёт `owner_hold{release:true, seq}` (инструмент `partner_hold`),
   где `seq` — номер этого `player_said`. Мод сверяет сообщение с буфером событий: hold снимается только
   по новому сообщению хозяина, которое не было стоп-словом или вопросом-шаблоном; поручение ли это —
   решает агент по своим правилам. Отказ `bad_args`, если: `helper` не указан; это не сообщение хозяина
   (`owner:true`); оно не новее hold; мод уже ответил на него как на слово (`auto_reply`/`word` — «стоп»,
   «что делаешь», «продолжай»); оно адресовано по имени другому помощнику; это сообщение уже сняло hold у
   этого помощника. Одно сообщение без имени снимает hold у каждого помощника по разу, адресованное по
   имени — только у того, к кому обращено. Ответ — `{released:[id]}` (`[]`, если hold не стоял). Без
   `release` операция возвращает `{hold:{id:{kind, tick, seq}}}`; `helper` тогда необязателен (без него —
   все помощники);
3. «стоп» или «иди сюда» ещё раз — прежний hold заменяется новым;
4. помощника убрали (`helper_remove`) — hold пропадает в течение секунды.

Смерть помощника hold не снимает: он остаётся и после возрождения, и новое тело тоже ждёт слова хозяина.
Агент ничего не возобновляет сам, пока hold стоит и нового сообщения хозяина нет.

Настройки мода (runtime-global): `partner-owner-words` (выключатель, по умолчанию вкл.),
`partner-stop-words`, `partner-come-phrases` (слова и фразы через запятую; пусто — списки по умолчанию).

### `attacked`, `health_low`
Всегда включены, набор рефлексов не нужен. `attacked{by, damage, health}`: `by` — имя того, кто
ударил, иначе тип урона, иначе `"unknown"`. Первое за эпизод — громкое; дальше шумные не чаще раза в
секунду (урон за секунду суммируется); эпизод кончается через 30 с без урона.
`health_low{health, max}` — здоровье < 40 %, один раз; повторно — только после восстановления до 50 %.

### `died`, `respawned`, `helper_lost`
- `died{pos, corpse?}` — тело погибло; приходит **после** `job_failed{code:"no_helper"}` снятых задач.
  `corpse` — где лежит труп с вещами (его нет, если движок не сообщил о трупе).
- Тело без игрока возрождается само через 10 с (600 тиков) у точки возрождения силы на той же
  поверхности (свободное место в радиусе 16), с пустым инвентарём (вещи остались в трупе) →
  `respawned{pos}`. Места нет — повтор каждые 5 с, до 12 раз, потом
  `reflex_done{type:"respawn", outcome:"failed", detail:{reason:"no_place"}}`; поверхности или силы
  больше нет — то же с `reason:"surface_gone"` │ `"force_gone"`. Помощника удалили или заспавнили
  заново, пока он был мёртв, — возрождение отменяется. Подробнее — PROTOCOL §6.9.
- У тела-игрока (PROTOCOL §7) возрождает движок, а `respawned` шлёт ядро: без `reason` — после
  возрождения движком, `reason:"player_joined"` — тело появилось после возврата игрока,
  `"body_restored"` — после другой пропажи тела.
- `helper_lost{reason}` — тело исчезло не по смерти: `destroyed` (тело уничтожено, запись снимается);
  у тела-игрока — `player_left`, `no_character`, `body_changed`, `player_removed`. Задачи при этом
  снимаются с `no_helper`. `player_removed` шлётся и для записей, которые уже ждут тело
  (`away`/`dead`).

### `game_reloaded`
Сейв перезагружен. Шлёт сервер, а не мод: курсор событий сбрасывается, задачи прежней «линии
времени» больше не существуют, события, собранные до перезагрузки в этом же ожидании,
отбрасываются.

## Рефлексы
Рефлексы срабатывают в моде без раздумий агента. Набор задаётся целиком: операция
`reflexes{set:[{type, ...параметры}]}` (MCP `partner_reflex`) полностью заменяет набор помощника
(до 16 рефлексов, ≤ 4 КБ), параметры проверяются по схеме типа (неизвестный тип или поле —
`bad_args`). `reflexes{}` без `set` ничего не меняет и возвращает текущий набор.

Обычный набор (агент ставит его в начале смены):

| type | параметры (границы = по умолчанию) | что делает |
|---|---|---|
| `flee` | `radius` 4..32 = 20, `distance` 8..64 = 30, `health` 0..1 = 1, `on_attack` = true, `to`: `"away"│"spawn"│"player"`, `resume` = true, `resume_health` 0..1 = 0.8 | враг в `radius` (или атака) и здоровье ≤ `health` → задача-отход, заменяет очередь; потом возврат к делу |
| `watch` | `radius` 4..32 = 32, `every_s` 1..600 = 10 | шумное `saw_enemy` о ближайшем враге |

Включаются только по слову хозяина (бой и домашние дела):

| type | параметры (границы = по умолчанию) | что делает |
|---|---|---|
| `ammo` | `radius` 4..32 = 20, `min` 1..200 = 10, `fill` 1..400 = 50, `item`: имя патронов, `chests` = true | заправляет свои турели патронами из инвентаря |
| `shoot` | `radius` 4..32 = 32, `skip`: [имя ствола] ≤ 10, `fire_near_own` = false | стреляет по ближайшему врагу, до которого достаёт ствол |
| `upkeep` | `radius` 4..96 = 96, `min` 1..50 = 2, `fill` 1..200 = 10, `packs` 1..100 = 10, `fuel`: имя топлива, `science` = true, `chests` = true | заправляет свои машины на горелках и кладёт науку в лаборатории из инвентаря помощника |

- Набор хранится в `storage.reflexes`, привязан к id помощника, а не к телу, и **переживает** смерть и
  возрождение, `helper_lost{destroyed}` (новый `helper_spawn` с тем же id наследует его), перезагрузку
  сейва и возврат тела-игрока; пока тела нет, проверки не идут. Сбрасывает его только `helper_remove`
  (и новый `reflexes{set}`).
- Проверки идут раз в 10 тиков для каждого живого помощника. Ошибка внутри проверки рефлекса не
  роняет мод: растёт счётчик `module_errors` в ответе `hello`, текст — в журнале игры (не чаще раза в
  минуту на тип).
- Задачи, которые ставит рефлекс, идут через ядро как обычные; их `req` = `"reflex:<type>"` (виден в
  `jobs`).
- Шумное `reflex_fired{type, detail}` — срабатывание, громкое `reflex_done{type, outcome, detail}` —
  итог (у `flee`).
- Опасные враги (для `flee`, `shoot` и подхода с дальней стороны) — сущности силы `enemy` типов `unit`,
  `turret`, `spider-unit`, `segmented-unit`, `segment` (кусаки, черви, пентаподы, разрушитель);
  `watch` видит ещё и гнёзда (`unit-spawner`).

### `flee`
Враг ближе `radius`, либо (`on_attack`) враг ударил издалека не больше 2 с назад, и здоровье ≤
`health` (доля; 1 — отступать при любом здоровье) → помощник бросает задачи (им приходит
`job_failed{cancelled}`) и идёт обычной задачей `walk` (`replace=true`, `req` `reflex:flee`) к
безопасной точке.
- Точка: к точке возрождения силы (`to:"spawn"`) или к хозяину (`to:"player"`), если она не ближе 8
  клеток к помощнику и дальше `radius` от врага; иначе на `distance` клеток прочь от врага, с
  отклонениями 0°, ±45°, ±90°, ±135°. Точка — в открытом чанке, свободная (в радиусе 4), без врагов
  ближе 8 (если видно).
- Путь не нашёлся или застрял — точки считаются заново (от нынешнего места и от ближайшего врага),
  уже испробованные пропускаются; до 8 точек на переход. Дошёл, а враг снова ближе `radius` — ещё
  переход, до 5.
- Шумное `reflex_fired{type:"flee", detail:{job, to, threat, dist}}` в начале, громкое
  `reflex_done{type:"flee", outcome, detail:{pos, legs, reason?}}` в конце. `reason`:
  `no_safe_point` │ `cancelled` (задачу сняли — агент решил иначе) │ `still_threatened` │ `no_helper`
  │ код ошибки ходьбы (`path_failed`, `stuck`, …). Не смог даже начать — `reflex_done` с `legs:0` и
  `threat`, громко один раз; та же причина повторяется не чаще раза в минуту.
- После удачного отступления новое — не раньше чем через 1 с, после неудачи — через 10 с.
- **Возврат к делу** (`resume`, по умолчанию включён). Перед отступлением мод запоминает задачи,
  которые оно снимет (активную и очередь, без задач рефлексов, не больше 4; у `mine` по `resource` /
  `item` — остаток `count`). Отступление удалось, врага ближе `radius` нет, здоровье ≥ `resume_health`
  и агент за это время ничего не поставил — мод ставит их снова (`req` `resume:flee`) и шлёт громкое
  `reflex_resumed{type:"flee", jobs:[{job, do}]}`. Агент поставил своё — возврат молча отменяется.
  `jobs:[]` с `reason`: `timeout` — здоровье и тишина не дождались 120 с; `too_often` — уже 3 возврата
  за 5 мин; `rejected` — ни одну задачу поставить не удалось; `owner_hold` — хозяин сказал «стоп» или
  «иди сюда» («Слово хозяина»), к делу без его слова не возвращаться. Тогда решает агент.
- Боевой режим агента: `flee{health:0.4}` (бежит только раненый), возврат — как обычно.

### `watch`
Шумное `saw_enemy{name, pos, dist}` о ближайшем враге в `radius` (включая гнёзда), не чаще раза в
`every_s` секунд.

### `ammo`
Заправщик турелей. Раз в 0.5 с самая пустая своя турель с патронами (`ammo-turret`) в `radius` от
тела, где патронов меньше `min`, получает их из инвентаря помощника до `fill` (не меньше `min`):
- в досягаемости (`reach_distance`) — сразу, как игрок рукой (тот же перенос, что у `insert`), по
  одной турели за раз; шумное `reflex_fired{type:"ammo", detail:{turret, item, count}}`;
- дальше — задача `insert` (`req` `reflex:ammo`), только если у помощника нет задач: задачи агента
  важнее. Помощник подходит сам, с дальней от врага стороны.
- Какие патроны: `item`, если задан, иначе любые предметы типа `ammo` из инвентаря (по алфавиту),
  которые турель принимает — решает движок (`can_insert`).
- Патронов нет — громкое `ammo_low{item?, turret}` не чаще раза в минуту; с `item` и `chests` — ещё и
  задача `collect{items:{item: fill×2}}` в 64 клетках (не чаще раза в 30 с, только при пустой очереди).
- Во время отступления молчит.

### `shoot`
Стрельба; по умолчанию не включён, агент включает его по слову хозяина. Каждую проверку: враги в
`radius` по удалению; первый, до которого достаёт один из стволов, — цель. Ствол — пара «ячейка оружия
+ та же ячейка патронов»; годится, если патроны есть, враг между `min_range` и `range` оружия
(`attack_parameters` из игры), ствол не в `skip` и это вообще оружие. Из годных — самый
короткобойный (вблизи огнемёт, дальше пулемёт). Дальше как игрок: выбор ствола (`selected_gun_index`,
как Tab) и `shooting_state = shooting_enemies` по позиции врага; патроны тратит движок.
- Не оружие — ствол, чьи патроны в действии (`get_ammo_type().action`) не несут ни доставки (снаряд,
  струя, луч, артиллерия, цепь), ни урона, огня, стикера (например, «патроны» наноботов).
- Патроны с огнём (`create-fire`) не бьют, если у цели в 6 клетках свои постройки или персонажи, —
  разве что `fire_near_own`.
- Цели нет — стрельба выключается. Шумное `reflex_fired{type:"shoot", detail:{target, gun, dist}}` —
  при смене цели или ствола.

### `upkeep`
Домашние дела; по умолчанию не включён, агент включает его по слову хозяина («следи за печами»,
«заправляй», «корми лаборатории»). Раз в секунду берёт машины своей силы из индекса построек в `radius`
от тела (STATE.md «status») и кладёт в ближайшую, которой нужно, топливо или науку — по одной машине за
проверку:
- топливо: у машины с горелкой в топливном слоте меньше `min` штук — добавляется до `fill`. Какое
  топливо, решает игра: категория, которую горелка принимает (`fuel_categories`), и `can_insert`
  топливного инвентаря; из подходящих берётся с наименьшей теплотой, `fuel` — только он. Реакторы не
  заправляются;
- наука: при текущем исследовании лаборатория, у которой пакета из его `research_unit_ingredients` меньше
  половины `packs` и которая такой пакет принимает, получает недостающее до `packs`. Без исследования
  лаборатории не кормятся; `science:false` выключает подачу;
- только предметы качества `normal` и только машины силы помощника; машины в невидимых чанках
  (PROTOCOL §6.7) пропускаются, как и всё живое;
- в досягаемости — сразу, как игрок рукой; шумное `reflex_fired{type:"upkeep", detail:{kind:"fuel"|
  "science", pos, item, count}}`. Дальше — задача `insert` (`req` `reflex:upkeep`), только если у
  помощника нет задач; для той же машины новая попытка — не раньше чем через 10 с;
- нужного нет в инвентаре и `chests` — при пустой очереди задача `collect` со складов в 64 клетках (не
  чаще раза в 30 с); топливо ищется по перечню видимых складов. Громкого события нет: чего не хватает,
  видно в `status` (`no_fuel`, `missing_science_packs`);
- во время отступления молчит. Агенту: держать очередь пустой, если хозяин просит именно заправку.

### Автосортировка инвентаря
Не рефлекс из набора, включена всегда: инвентарь тела без игрока раз в 5 с сортируется
`sort_and_merge` (как кнопка сортировки: порядок ячеек и слияние стопок). Тело-игрок не трогается —
у него своя настройка в игре.

## Ожидание на стороне сервера
- MCP-инструмент `partner_wait(timeout=30 (0..55), quiet=true, since?)`.
- Сервер хранит **курсор** последнего выданного агенту `seq` на помощника (при старте — текущий
  `seq` из `hello`). `since` по умолчанию = курсор; `since=0` значит «с текущего момента», а не
  «с начала буфера».
- Опрос `events` по соединению `poll` каждые 0,5 с до важного события (`quiet=true`) или любого
  (`quiet=false`), либо до `timeout`. Полная страница (200 событий) дочитывается сразу.
- Ответ агенту: `{seq, tick, events:[...важные + до 6 последних шумных], timed_out:bool, more?, lost?,
  warning?}`.
  - **Страницы:** не больше 40 важных событий и не больше 24 КБ за ответ; курсор сдвигается только
    до последнего выданного. `more:true` — в буфере есть ещё, вызвать `partner_wait` сразу.
    `partner_wait` никогда не отвечает `response too large`.
  - Одно событие больше 24 КБ выдаётся урезанным: `{seq, tick, helper, kind, loud,
    data:{job, do, code, type, outcome, reason, truncated:true}}`.
  - `lost:true` — курсор старше буфера, часть событий потеряна (смотреть `partner_state`).
  - `warning:"game_paused"` — игра на паузе (PROTOCOL §5).
  - У `build_blueprint` без найденного сдвига сервер дописывает `detail.fit:null` (ACTIONS.md
    «build_blueprint»).
- Пустой ответ = «ничего нового» — агент ждёт снова без комментариев.
- 55 с — граница **всего вызова**, включая последний опрос `poll` (таймауты MCP).
